# A/V 同期と再生の判断

対象実装: `20985ca8`。現在の実装を見直す際の判断をまとめる。
予算と処理の説明は [音声と映像の再生](PLAYOUT.md)、過去の閾値の根拠と測定表は
[2026 年 10 月の判断記録](archive/playout/AV_SYNC_DECISIONS.md) を参照すること。

## 1. 基準の差と既知の待ちを分ける

TIMESTAMP と到着の差には、経路の遅延だけでなく送受信時計のずれも含まれる。
その差の全額を相手トラックの待ちへ移さず、基準の補償と既知のバッファ差、実出力の残差を分ける。
同期の補償上限は実遅延の上限ではない。

基準を共有できているか、解除理由は何か、補償量が上限に張り付いていないかを確認する。
片方が遅れたことへの対処として、両方の待ちを一律に増やさない。

## 2. 揺らぎと媒体の欠落を分ける

自動予算を増やす根拠は、到着の分布と実出力時計の先行量である。
パケット欠落で失った媒体時間や、すでに補間した量を経路の揺らぎへ足さない。
購読開始時に cache から追いつく入力と、停止後にまとめて返る復号出力も分布から除く。

遅延不足と判断する前に、受信時刻、復号出力時刻、媒体 timestamp の欠落、
メインスレッドの停止を分けて記録する。意図した復号前遅延も差し引く。

## 3. 回復を遅らせず、実適用量を反映する

音声の語尾を切らないため、遅着した音を遅れだけで捨てない。
予約の重なりを防ぎ、圧縮する場合は予約の余裕を超えて削らない。
再同期後の深さは、再開前の無音を追加する代わりに、適用可能な音の伸長で回復する。
予約基準へ反映するのは圧縮と伸長の要求量ではなく、実際に適用した量である。

音声の回復中は実予約深さを同期先へ反映する。
停止時も実出力時計を確認し、resume の Promise の完了や壁時計だけで再生完了と判断しない。

## 4. NetEq の採用範囲を区別する

独自処理が NetEq より優れているという測定結果はない。
出力側の欠落判定と補間、実音への接続、周期による圧縮と伸長には NetEq の仕組みを採用する。
独自処理を残す場合は、同じ入力と同程度の実出力遅延で利点を確認する。

現行は仕組みの部分的な採用であり、NetEq 全体の実装ではない。
符号化済みパケットからの出力判断、コーデック内部の PLC / FEC、相関で実音の位置を合わせる
Merge、適応遅延制御まで同等に実装したとは扱わない。
上流との対応と採用時の比較は [NetEq の調査記録](archive/playout/NETEQ_PLAYOUT_ADOPTION.md)、
伸長の追加は [レビュー対応の記録](archive/playout/PLAYOUT_REVIEW_FIXES.md) にある。

## 5. 前提から外れたときに見る値

| 観測                                             | 見直す対象                                         |
| ------------------------------------------------ | -------------------------------------------------- |
| 同期用の待ちが上限に張り付く                     | 基準の差、バッファ差、出力時計、catalog の明示下限 |
| 基準の共有解除が続く                             | TIMESTAMP の種類、時計のドリフト、保持と解除の経過 |
| 配信側の timestamp 補正が動き続ける              | capture の時刻と配信側の処理停滞                   |
| 復号器の追いつきが繰り返される                   | 入力の遅れと復号が加えた遅れ、意図した保持         |
| レート不一致、Context の停止、狭帯域の警告が出る | [音声出力の診断](AUDIO_GLITCH_CAUSES.md)           |

DevTools の `preconditionWarnings` は既存の計器から前提の逸脱を示す。
警告だけでノイズの原因を確定せず、対象区間の入力と出力を照合する。

## 変更を採用する条件

- 同じ入力で修正前後と Chrome の WebRTC を比較し、配送、復号、予約、実出力を区別する
- 実遅延、活動確認付きの無音、分類できない区間、処理負荷を併記する
- バッファを増やして得た連続性や、音を消して減った段差を音質の優位性としない
- 純音だけでなく日本語の有声音と子音を含め、短フレーム、停止、復旧も確認する
- 収録の欠落と波形照合の棄却を隠さず、未確認の聴感や Bluetooth の品質を断定しない

測定の手順と計器の意味は [再生の計測](PLAYOUT_MEASUREMENT.md) にまとめる。
