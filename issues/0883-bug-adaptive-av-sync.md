# 音声の再生開始と遅延適応で A/V 同期が崩れるのを修正する

- Created: 2026-10-21
- Branch: feature/fix-adaptive-av-sync

## 目的

音声再生を有効にした瞬間の過大な映像遅延を減らし、音切れを避けるために音声の目標を広げた場合も映像を同期させる。

## 現状

- 到着の推定は 80 ms、閉ループは 100 ms から始まり、観測の開始だけで映像の待ち時間が増える
- `PlayoutTimeline.alignSyncExtras` は時計のずれとバッファの差を合わせて 100 ms で打ち切るため、音声目標が 160 ms に広がると A/V の差が残りうる
- `observeAudioPlayout` は音声目標だけを更新し、同期の更新を次の復号出力まで待つ
- 実際の音声出力が予約時の予定より遅れても、映像は予定にだけ合わせている
- 再生の停止で閉ループを初期化しないため、過去の穴で深くなった目標が再開後にも残る

## 設計方針

- 閉ループを安全下限 50 ms から始め、到着推定の開始値は初期の音切れを抑える 80 ms を保つ
- 基準の差には 100 ms の保護を残し、既知のバッファの差はキューの上限まで補償する
- 出力の時計で換算できた音声の実績と予約時の予定の残差を平滑化し、映像の合わせ先へ反映する
- 再生の観測を反映した呼び出し内で同期も更新する
- 音声を停止したら出力の残差と閉ループの状態を消し、計器の過去の累積を再開後の穴に数えない
- 実ブラウザと実リレーで、同期精度と遅延だけでなく穴、圧縮、破棄も評価する

## 完了条件

- 安定した到着では、最初の再生の観測で 100 ms へ跳ね上げない
- 既知のバッファ差で音声目標が 160 ms になっても、キューに余裕があれば予定の差が 5 ms 以内に収まる
- 出力の残差を繰り返し観測しても遅延を積み上げない
- 時計の段差とドリフトへの保護、音声だけの再生の下限、明示した遅延予算を保つ
- 回帰テスト、型検査、lint、ビルドが通る

## 解決方法

- 共有の表示時刻の下限を 1 つにし、各トラックの jitter と既存の補償が互いへ再加算されないようにした
- 基準の差と既知のバッファの差を分け、実際に先行する側を待たせる。警告も同じ補償予算から判定する
- 有効な AudioContext の時計で換算した予約と予定の差を平滑化し、1 秒で失効させる
- 音声停止時に閉ループを消し、再開前の分布と累積の差を新しい穴として扱わない
- 開始値の比較により、到着推定は既存の 80 ms を維持し、閉ループだけ 100 → 50 ms にした
- cache の追いつきで到着基準が下がった分を共有の表示時刻へ反映し、古い基準を追加遅延へ持ち越さない
- 壁時計の観測が無い音声にも閉ループの適用値を渡し、穴で広げた上限を現在の指定上限へ収める
- 44.1 kHz は解析信号だけを変換して時間圧縮と補間を可能にし、受信停止後の回復を結合テストで検証する
- 実 AudioData と Web Audio へ Session の結合テストを移し、AudioContext の再生成と停止・再開も検証する
- 再開直後の未確定な出力時計は代用へ戻し、閉じた AudioData は副作用前に拒否して後続の予約と計器を壊さない
- 整数周期の完全相関を維持して既存レートの音質回帰を防ぎ、同じ Context の停止と再開では古い時計対応を代用値へ持ち越さない
- 単体・プロパティテスト 4,175 件、関連ブラウザテスト 13 件、実リレーの TIMESTAMP / A/V 同期回帰 1 件が通過した
- 型検査、lint、フォーマット、SDK と devtools のビルドを確認した

45 秒の実リレー計測と制約は `docs/AV_SYNC_DECISIONS.md` に記録した。受信停滞のあった回も含め、
全条件で遅延や音切れが改善したという結論にはしていない。HTMLAudioElement より後の出力デバイスと
画面の実際の発光を含む物理的なリップシンクは未検証である。

全体テストとブラウザ検証の同時実行では、未変更の Publisher の停止・再開テストが 1 回失敗した。
同時実行を終えた後の全体テストは 4,175 件すべて通過した。
