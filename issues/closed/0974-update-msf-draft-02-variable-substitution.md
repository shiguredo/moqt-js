# 変数置換の文字制約を draft-02 に合わせる

- Created: 2026-11-16
- Completed: 2026-11-16
- Branch: feature/update-msf-draft-02
- Polished: {YYYY-MM-DD}

## 目的

draft-02 §5.4.1 は変数名の文字制約を撤廃し、変数値に `+`、`/`、`=`、`.` を追加した。§5.4.2 は fragment の pair を最初の `=` で分割すると明記した。現行実装は draft-01 の制約のままで、`resourceId` 以外の変数名や、URL に載る base64url 以外の値を拒否する。publish track の namespace に `%resourceId%` を埋める用途 (§5.6.17) や、認可トークンを変数で配る用途 (§5.2.43) で、正しい catalog を誤って拒否する。

## 現状

- `src/msf/variables.ts` の `VARIABLE_NAME_PATTERN` は `^[A-Za-z0-9_-]+$` で、変数名を英数字、ハイフン、アンダースコアに限定する
- 同ファイルの `VARIABLE_VALUE_PATTERN` は `^[A-Za-z0-9_@-]*$` で、値に `+`、`/`、`=`、`.` を許可しない
- `VARIABLE_REFERENCE_PATTERN` は `%([A-Za-z0-9_-]+)%` で、変数参照として解釈する名前も同じ文字集合に限定する
- `resolveCatalogVariables` は入力の変数名と値を上記のパターンで検証し、違反を `Error` にする
- fragment 側の `parseMsfFragmentValue` は key を最初の `=` で分割しているため、この点は既に draft-02 と一致している

## 設計方針

- 変数名の検証を削除する。§5.4.1 は変数名の文字集合を定めていないため、`%` で囲まれた任意の文字列を変数名として扱う
- `VARIABLE_REFERENCE_PATTERN` を、`%` と `%` に挟まれた任意の文字列を拾う形にする。空文字列 (`%%`) を変数参照として扱うかは決める必要がある。draft-02 は空の変数名を禁じていないが、実装では名前が空の参照を不正として拒否する方が安全である
- 変数値の検証を `^[A-Za-z0-9_@+/.=-]*$` に広げる。draft-02 が許可しない文字 (`,`、`;`、`"`、`&` など) は引き続き拒否する
- 値の検証を残す理由を JSDoc に書く。§5.4.1 が注入対策として文字集合を定めているため、実装が受け取る値の検証を落としてはならない
- fragment から変数への変換経路 (fragment の parameter を `variables` に写す処理) は本 issue の対象外とする。配線は既存 issue 0853 で扱う

## 完了条件

- 変数値 `"a.b"`、`"a+b"`、`"a/b"`、`"a=b"` を受理する。単体テストで固定する
- 変数値 `"a b"`、`"a,b"`、`"a;b"`、`"a%b"` を拒否する。単体テストで固定する
- 変数名 `"x.y"`、`"x/y"` を受理する。単体テストで固定する
- `%` で囲まれた空の参照を拒否する。単体テストで固定する
- `npx vp check` / `npx tsc --noEmit` / `npx vp test --run` が通る

## 解決方法

- `src/msf/variables.ts` から変数名の文字種検証を削除し、変数参照のパターンを `%([^%]+)%` にした。draft-02 §5.4.1 は変数名の文字集合を定めていない
- 変数値のパターンを `^[A-Za-z0-9_@+/.=-]*$` に広げた。draft-02 で追加された `+` `/` `=` `.` を受理し、`,` `;` `"` `&` は §5.4.1 の注入対策として引き続き拒否する
- 空の参照 (`%%`) は変数参照として解釈せず、literal の `%` として拒否する
- 未知フィールドの `%resource.id%` が置換されること、追加文字の受理と禁止文字の拒否を単体テストで固定した
