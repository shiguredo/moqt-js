# CHANGES.md を更新しないルールと実績の矛盾を解消する

- Created: 2026-10-14
- Completed: {YYYY-MM-DD}
- Branch: feature/update-changelog-draft-rule

## 目的

`CODEBASE.md` の「MOQT RFC ドラフト中の特別ルール: CHANGES.md を更新しない」と、実際の履歴が矛盾している。変更を入れるたびに CHANGES.md を更新するかの判断が割れ、実際に 0858 では更新の可否をユーザーへ確認する必要があった。どちらを正とするかを決めて、規約と実績を一致させる。

## 現状

- `CODEBASE.md` の「MOQT RFC ドラフト中の特別ルール」は `CHANGES.md を更新しない` と定めている
- `CHANGES.md` は 8d54b822 (`RFC ドラフト中は変更履歴を残さない`) で 3219 行が削除され、ルールが追加された。以降の `## develop` には 61e1d576 (`基準の共有の解除を往復の検出で判断する`) が `[FIX]` エントリを 1 件追記している
- つまり「ドラフト中は一切更新しない」と「利用者に見えるバグ修正は `[FIX]` で記録する」が併存している
- 0858 の修正 (音声の符号化形式をマイクの取り出した形式に追従させ、`start()` の失敗条件を増やす) は利用者に見える挙動の変更だが、このルールに従って CHANGES.md には記録していない
- ドラフト期間が終わった時点で、ドラフト中に入れた変更の履歴を拾い直す手順はどこにも無い

## 設計方針

どちらかに揃える。判断はユーザーが行う。

- ルールを狭める: ドラフト中でも `[FIX]` だけは記録する (利用者に影響する修正の履歴を残す)。`[CHANGE]` / `[ADD]` / `[UPDATE]` は記録しない
- 実績を撤回する: `## develop` の `[FIX]` エントリを取り消し、ルール (一切更新しない) を維持する。この場合、ドラフト期間中の変更をリリース時にどう記録するか (ドラフト期間終了時にまとめて書く / 書かない) をルールに明記する

決めた内容を `CODEBASE.md` と `CHANGES.md` の両方に反映し、`AGENTS.md` から参照される規約として矛盾が残らないようにする。

## 完了条件

- ルール (更新しない / `[FIX]` だけ記録する) が決まり、`CODEBASE.md` の記述がそれに一致していること
- `CHANGES.md` の `## develop` の内容が決めたルールと一致していること (記録するなら 0858 などドラフト中の修正を追記し、記録しないなら 61e1d576 のエントリを取り消す)
- ドラフト期間中の変更をリリース時にどう扱うかが、`CODEBASE.md` または `CHANGES.md` を読めば分かること
- `vp check` が通ること (ドキュメントのみの変更でも整形検証の対象)
