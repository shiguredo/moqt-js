## 目的

時雨堂のドキュメント規約 (shiguredo-doc) は、並列要素の区切りに中黒「・」を使わず、2 語の対句・対比は半角スラッシュで、3 語以上の軽い列挙は読点「、」でつなぐことを定めている (4 語以上の列挙や各要素に説明を伴う列挙は箇条書きに分解する)。リポジトリの日本語コメント・テスト名・ドキュメントには、2 語以上の日本語の並列を中黒でつないだ記述が残っており、規約と揃っていない。表記の揺れを放置すると、同じ並列が場所ごとに中黒・読点・スラッシュで書かれる状態が続く。

## 現状

2026-11-15 に `rg -c '・'` の出力を合計して確認した結果は次のとおり。

- `src/` 配下で中黒を含む行は 788 行ある (日本語コメント 701 行、`test()` のテスト名 87 行。例: `src/index.ts` の「検証・range・Group ID などの内部ヘルパーはモジュール内に留める」、`src/msf.ts` の「トラック検索・Catalog 生成・Group 番号付け」)
- `devtools/src/` 配下で中黒を含む行は 171 行ある (日本語コメント 161 行、テスト名 8 行、テスト内の説明文字列 2 行)
- `CHANGES.md` の `## develop` は draft-23 対応の 1 行のみで、中黒を含む行は無い
- `docs/` に 110 行 (うち `docs/archive` 70 行)、`README.md` に 0 行ある (例: `docs/LOW_LEVEL_API.md` の「全 Track・全 Fetch」)
- UI 表示・ログ・エラーメッセージとして出力する文字列リテラルには中黒は無い (ログと devtools の UI は英語表記のため)。コード上の日本語文字列のうち中黒を含むのはテスト名とテスト内の説明文字列だけである
- `tests/e2e/` (56 行) と `examples/` (1 行) の日本語コメントにも中黒があるが、今回の対象外とする

- 中黒には日本語の並列以外の用途も混ざっている (例: `ID・priority` のような英数字・識別子の列挙)。こうした箇所は機械的に判断できないため、変更せず判断が必要な箇所として残す

## 設計方針

- 対象は日本語の並列を表す中黒に限る。次のものは対象外とする
  - 単一の固有名詞・複合語の内部
  - 英数字・識別子だけからなる列挙 (例: `ID・priority`、`lookup・FIN`。既存の「 / 」表記は維持し、中黒のままの箇所は判断が必要な箇所として残す)
  - URL・コードブロック・引用
- 日本語の語を含む列挙は、識別子が混ざっていても対象とする (例: `src/index.ts` の「検証・range・Group ID」は「検証、range、Group ID」にする)
- 2 語の日本語の並列は半角スラッシュでつなぐ (対句・対比に限らず、2 語の日本語の並列全体を対象とする。前後に半角スペースを入れた ` / ` にする)
- 3 語の軽い列挙は読点「、」でつなぐ
- 4 語以上の列挙、または各要素に説明を伴う列挙は shiguredo-doc の定めどおり箇条書きに分解する。コメントや文字列内で箇条書きに分解できない場合は変更せず、判断が必要な箇所として残す
- 対象範囲は `src/` / `devtools/src/` の日本語コメント、テスト名、テスト内の説明文字列、`docs/` (ただし `docs/archive/` を除く)、`README.md` とする。
  テスト名とテスト内の説明文字列は挙動や表示に影響しないため対象に含める。UI 表示・ログ・エラーメッセージの文字列リテラルは対象外 (中黒のある箇所は無い)。
  `CHANGES.md` は `CODEBASE.md` の MOQT RFC ドラフト中の特別ルール (CHANGES.md を更新しない) により対象外とする。
  `docs/archive/` は記録時点の文書のため対象外とする (`docs/archive/README.md` と shiguredo-doc の「旧文書の扱い」に従う)
- 既存の表記揺れを 1 つだけ直すことなく、対象範囲を一括で揃える (shiguredo-doc の「揺れているなら全箇所揃えること」に従う)
- 機械的に判断できない箇所は変更せず、判断が必要な箇所を issue に残す
- 挙動・公開 API・型は変えない。コメント・テスト名・テスト内の説明文字列・文書の言葉遣いのみの変更である

## 完了条件

- 対象範囲の日本語の並列を表す中黒が、半角スラッシュ (2 語の日本語の並列)、読点 (3 語の軽い列挙)、または箇条書き (4 語以上・説明を伴う列挙) に揃っている
- 単一の固有名詞・複合語の内部の中黒、英数字・識別子だけからなる列挙、URL、コードブロック、引用は変更していない
- `CHANGES.md` と `docs/archive/` は変更していない
- `vp check` / `vp test run` / `vp run build:devtools` が通る (コメント・テスト名・テスト内の説明文字列・文書のみの変更で挙動が変わらないこと)
- 機械的に判断できず変更しなかった箇所があれば、その一覧と理由が issue に残っている

## 参照

- `AGENTS.md` と `shiguredo-doc` (並列要素に中黒を使わない、2 語の並列 (対句・対比を含む) は半角スラッシュ、3 語の軽い列挙は読点、4 語以上や説明を伴う列挙は箇条書き、半角と全角の境界には半角スペース)
- `docs/archive/README.md` (archive は記録時点の文書であり、現行の定数や件数へ一括置換しない)
- 対象範囲の例: `src/index.ts` / `src/msf.ts` / `docs/LOW_LEVEL_API.md`
- 現状の調査方法: `rg -c '・' <dir> | awk -F: '{s+=$2} END {print s}'` で合計行数を数える (`src` / `devtools/src` / `docs` / `README.md`)

## 対象外の確認

`CHANGES.md` は `CODEBASE.md` の MOQT RFC ドラフト中の特別ルール (CHANGES.md を更新しない) により対象外とする。`docs/archive/` は `docs/archive/README.md` が「各文書は記録時点の実装、仮説、計測結果を残す」「測定表の前提と比較元を維持し、現行の定数や件数へ一括置換しない」と定めており、shiguredo-doc の「旧文書の扱い」にも従い対象外とする。したがって `docs/` の対象は 40 行である。
