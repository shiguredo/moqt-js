## 目的

時雨堂のドキュメント規約 (shiguredo-doc) は、並列要素の区切りに中黒「・」を使わず、2 語の対句・対比は半角スラッシュで、3 語以上の軽い列挙は読点「、」でつなぐことを定めている (4 語以上の列挙や各要素に説明を伴う列挙は箇条書きに分解する)。リポジトリの日本語コメント・テスト名・ドキュメントには、3 項目以上を中黒でつないだ記述が残っており、規約と揃っていない。表記の揺れを放置すると、同じ並列が場所ごとに中黒・読点・スラッシュで書かれる状態が続く。

## 現状

2026-11-14 に `rg -c '・'` で確認した結果は次のとおり。

- `src/` 配下で中黒を含む行は 786 行ある (日本語コメント 699 行、`test()` / `it()` のテスト名 87 行。例: `src/index.ts` の「検証・range・Group ID などの内部ヘルパーはモジュール内に留める」、`src/msf.ts` の「トラック検索・Catalog 生成・Group 番号付け」)
- `devtools/src/` 配下で中黒を含む行は 171 行ある (日本語コメント 163 行、テスト名 8 行)

- `docs/` に 110 行 (うち `docs/archive` 70 行)、`README.md` に 0 行ある (例: `docs/LOW_LEVEL_API.md` の「全 Track・全 Fetch」)
- UI 表示・ログ・エラーメッセージとして出力する文字列リテラルには中黒は無い (ログと devtools の UI は英語表記のため)。コード上の日本語文字列のうち中黒を含むのはテスト名だけである
- `tests/e2e/` (56 行) と `examples/` (1 行) の日本語コメントにも中黒があるが、今回の対象外とする

## 設計方針

- 対象は日本語の並列を表す中黒に限る。次のものは対象外とする
  - 単一の固有名詞・複合語の内部
  - 英数字・識別子の列挙 (既存の「 / 」表記を維持する。`ID・priority` のように識別子を中黒でつないだ箇所もここに含め、判断が必要な箇所として残す)
  - URL・コードブロック・引用
- 2 語の対句・対比は半角スラッシュ、3 語以上の軽い列挙は読点「、」にする
- 4 語以上の列挙、または各要素に説明を伴う列挙は shiguredo-doc の定めどおり箇条書きに分解する。コメント内で箇条書きに分解できない場合は変更せず、判断が必要な箇所として残す
- 対象範囲は `src/` / `devtools/src/` の日本語コメントとテスト名、`docs/`、`README.md` とする。テスト名は挙動や表示に影響しないため対象に含める。UI 表示・ログ・エラーメッセージの文字列リテラルは対象外 (中黒のある箇所は無い)。`CHANGES.md` は `CODEBASE.md` の MOQT RFC ドラフト中の特別ルール (CHANGES.md を更新しない) により対象外とする
- 既存の表記揺れを 1 つだけ直すことなく、対象範囲を一括で揃える (shiguredo-doc の「揺れているなら全箇所揃えること」に従う)
- 機械的に判断できない箇所は変更せず、判断が必要な箇所を issue に残す
- 挙動・公開 API・型は変えない。コメント・テスト名・文書の言葉遣いのみの変更である

## 完了条件

- 対象範囲の日本語の並列を表す中黒が、読点 (3 語以上)、半角スラッシュ (2 語の対比)、または箇条書き (4 語以上・説明を伴う列挙) に揃っている
- 単一の固有名詞の内部の中黒、英数字・識別子の列挙、URL、コードブロックは変更していない
- `vp check` / `vp test run` / `vp run build:devtools` が通る (コメント・テスト名・文書のみの変更で挙動が変わらないこと)
- 機械的に判断できず変更しなかった箇所があれば、その一覧と理由が issue に残っている
