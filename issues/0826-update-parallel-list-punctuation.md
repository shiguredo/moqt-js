## 目的

時雨堂のドキュメント規約は、並列要素の区切りに中黒「・」を使わず、3 語以上の軽い列挙は読点「、」でつなぐことを定めている (2 語の対句・対比は半角スラッシュ)。リポジトリの日本語コメント・変更履歴・ドキュメントには 3 項目以上を中黒でつないだ記述が残っており、規約と揃っていない。表記の揺れを放置すると、同じ並列が場所ごとに中黒・読点・スラッシュで書かれる状態が続く。

## 現状

- `src/` 配下のコメントに中黒を含む行が 407 行ある (例: `src/index.ts` の「検証・range・Group ID などの内部ヘルパーはモジュール内に留める」、`src/msf.ts` の「トラック検索・Catalog 生成・Group 番号付け」)
- `CHANGES.md` の `## develop` に中黒を含む行が 80 行ある
- `docs/` と `README.md` にも同種の記述がある
- 中黒には「単一の固有名詞の内部」(例: `MOQT / LOC` のような英語の列挙、複合語) のように、そのまま残すべき用法も混ざっている
- コードの文字列リテラル (UI 表示・ログ・エラーメッセージ) にも中黒がある

## 設計方針

- 対象は日本語の並列を表す中黒に限る。次のものは対象外とする
  - 単一の固有名詞・複合語の内部 (例: 製品名・プロトコル名の一部)
  - 英数字・識別子の列挙 (既存の「 / 」表記を維持する)
  - URL・コードブロック・引用
- 3 語以上の軽い列挙は読点「、」にする。2 語の対句・対比は半角スラッシュにする
- 対象範囲は `src/` / `devtools/src/` の日本語コメント、`CHANGES.md`、`docs/`、`README.md` とする。コードの文字列リテラル (UI 表示・ログ・エラーメッセージ) は挙動と表示に影響するため、別の判断として分ける
- `shiguredo-doc` の「既存の表記揺れを 1 つだけ直すこと」に反しないよう、対象範囲を一括で揃える。機械的に判断できない箇所は変更せず、判断が必要な箇所を issue に残す
- 挙動・公開 API・型は変えない。コメントと言葉遣いのみの変更である
- `CHANGES.md` は機能に直接影響しない変更のため `### misc` に記載する

## 完了条件

- 対象範囲の日本語の並列を表す中黒が読点 (3 語以上) または半角スラッシュ (2 語の対比) に揃っている
- 単一の固有名詞の内部の中黒、英数字の列挙、URL、コードブロックは変更していない
- `vp check` / `vp test run` / `vp run build:devtools` が通る (コメントのみの変更で挙動が変わらないこと)
- `CHANGES.md` の `## develop` の `### misc` に変更を記載している
- 機械的に判断できず変更しなかった箇所があれば、その一覧と理由が issue に残っている
